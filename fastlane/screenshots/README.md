## 五屏的顺序

顺序就是产品页上的顺序，所以第一屏必须独立扛住整个概念。

| # | 界面 | 展示什么 |
|---|---|---|
| 1 | 首页 | 可回收多少、有哪几类活 |
| 2 | 滑动卡组 | 左滑清、右滑留 |
| 3 | 完全一致的重复 | 默认打勾，唯一敢自动清的一类 |
| 4 | 同一张的不同版本 | 看大图挑，可多留 |
| 5 | 同一时刻多张 | 连拍交还给你，不自动删 |

第五屏**不是**「清理记录」。历史在全新设备上是空的，唯一能填满它的 DEBUG 开关会
造出「78 GB 相册、41,800 张照片、16 周清理记录」的假数据 —— 放上产品页等于把编造的
使用记录当成真的。「同一时刻多张」有真实内容，而且是这个 app 真正的差异点。

## 验收判据：拿输入的数字断言输出

**「截图看起来合理」不是通过条件。** 有一批截图看着完全没问题，实际上相册里每张
照片有三份（`addmedia` 是累加的，而且在失败的运行里也照样执行成功），重复组从
7 组虚高到 59 组。只有核对数字才能发现：

| 项 | 必须等于 | 来源 |
|---|---|---|
| 相册规模 | **85 张** | 79 张演示 + 6 张自带壁纸 |
| 完全一致的重复 | **7 组** | 生成时就是 7 组 |
| 同一时刻多张 | **7 组** | |
| 聊天截图 | **9 项** | 生成数量 |
| 状态栏 | 9:41、平常满格电池 | |
| 日期语言 | 英文 `Fri Aug 28` / 中文 `8月28日周五` | |
| 尺寸 | 上表，一个像素都不能差 | |

## 脚本里五个不能删的地方

1. **开头 `erase`** —— 否则 `addmedia` 累加成上面那个污染。⚠️ erase 是**设备级**的，
   会清掉那台模拟器上所有 app 的沙盒，不只是这个。跨 session 共享设备时先协调。
2. **先 boot 再 `xcodebuild`** —— 设备关机时解析不到 destination，报
   `Supported platforms ... is empty`，然后 install 拿到空路径、launch 失败，
   而**脚本退出码是 0、零产出**。
3. **每步断言** —— app 包存在、launch 成功、每张截图非空。缺文件必须停。
4. **启动重试** —— SpringBoard 在 install 或重启后会短暂拒绝
   （`FBSOpenApplicationServiceErrorDomain code=1`），几秒自愈。
5. **语言切换写宿主机 plist 再重启** —— `simctl spawn defaults write` 不生效
   （实测值不落地）。而且 `status_bar override` **不能跨重启存活**，所以每次
   boot 后都要重设，不能开头设一次。

## 游戏截图那一行为什么不出现

演示库里有 5 张横屏游戏截图，但模拟器上认不出来。游戏规则最重的两条证据在那里
都拿不到：`aspect > 1.2` 只值 0.45，另一条 `gameishLabels` 来自
`VNClassifyImage`，**在模拟器上永远失败且不报错**，那 0.3 分静默消失。

不要用 `Tools/AlgoLab` 的结果来判断模拟器上会怎样 —— 它跑在 macOS 上，
那里**有神经引擎**，`FeaturePrint` 能跑，所以它报 5/5 全对。我拿错过这把尺子。

现状是「少一行，但没有错数字」；改成竖屏会变成「聊天 13、游戏 1」两个错数字。
少一行是诚实的，错数字不是。
